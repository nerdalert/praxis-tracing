DEMO SEQUENCE · 04 / 05
One presenter control per state change

Apply pressure. Probe. Recover.

Each step waits for live evidence before the next action is enabled.

01 · BASELINE

Show two sites

Readiness, active requests, comparable capacity, candidate scores, and matching overlay revisions.

02 · PRESSURE

Apply bounded load

Up to four concurrent direct requests go to the selected Mocker. Four is the demo comparison reference, not a Mocker replica count or queue limit.

03 · ROUTE

Send a fresh probe

Inspect the unique request ID, HTTP response, selected site, backend, and emitted headers.

04 · RECOVER

Release and verify

Wait for fresh zero-active metrics, restored rank, and Gateway revision convergence.

05 · OPTIONAL LIVE CONTROL

PROOF & LIMITS · 05 / 05
What the viewer can verify

Show the signal, decision, revision, and request together.

The historical recording shows a real routing response to live Frontend signals, with precise limits on what it proves.

Evidence shown in the recorded run

Source hash and pinned image identities · Frontend readiness and active requests · capacity/profile · Grid score and rank · published overlay revision · Gateway-consumed revision · fresh request ID and emitted route attribution · zero-active recovery.

Historical UI recording

The supplied screen recording is from the completed run shown in its run badge. Its LIVE labels describe the capture time; they do not describe a current deployment. In a current run, LIVE values need a fresh source time, STALE keeps its age visible, UNAVAILABLE has no numeric value, and CONFIGURED marks the declared comparison profile.

Correlated proof chain

Frontend /metrics sample→Grid candidate score / rank→published revision→Gateway consumed revision→request ID + route evidence actually emitted

What this does not prove

Mocker returns synthetic inference responses. This is not GPU saturation, model quality, or a weighted-share precision test.

Keep the failure story precise

Optional interruption changes one declared peer signal endpoint. It is not a network ACL or live SWIM demonstration. Frontend stage counts are not llm-d/EPP queues.
